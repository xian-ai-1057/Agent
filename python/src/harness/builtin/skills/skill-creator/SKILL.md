# 建立 skill

skill 是一段「需要時才展開」的任務指示。agent 平常只看到每個 skill 的
名稱與一句 description，判斷用得到時才載入完整內容。所以 skill 寫得好
不好，取決於兩件事：description 能不能讓 agent 在對的時機想到它，以及
內文能不能讓 agent 照著做出穩定的結果。

## 步驟

1. **先問清楚用途。** 這個 skill 要處理什麼工作？使用者通常會怎麼開口？
   成功的結果長什麼樣子？有沒有現成的文件、範本或範例可以參考？資訊
   不足時先問，不要自己假設。
2. **看看現有的 skill。** 用 `find_files` 找 `skills/*/SKILL.md`，避免
   重複，也沿用專案既有的寫法。
3. **決定名稱。** 小寫英文與連字號，描述動作或領域，例如
   `monthly-report`、`refund`。資料夾名稱與 `name` 相同。
4. **寫 SKILL.md**（格式見 `template.md`），存到 `skills/<名稱>/SKILL.md`。
5. **把長的參考資料拆出去。** 政策全文、範本、對照表放成同一個資料夾
   裡的其他檔案，SKILL.md 只寫「什麼時候去讀哪個檔案」，agent 會用
   `read_skill_file` 讀取。
6. **回報結果。** 列出建立了哪些檔案，並提醒使用者：要在 agent 設定的
   `skills` 欄位加上這個名稱（或不寫 `skills` 欄位，讓 agent 使用全部
   skill），若 skill 有 `tools`，那些工具必須存在於專案裡。

## 寫好 description

- 同時寫「做什麼」與「什麼時候用」，例如「處理退款申請，依退款政策
  判斷能不能退。使用者提到退款、退貨、退費時使用」。
- 寫進使用者實際會說的字眼，agent 是靠字面比對來決定要不要載入。
- 一到兩句，不要寫步驟細節，那是內文的工作。

## 寫好內文

- 用祈使句寫步驟，一步一件事，依執行順序排列。
- 寫清楚判斷標準與例外情況，例如「金額超過一萬元時先問使用者」。
- 說明產出的格式，最好附一個簡短的範例。
- 只寫 agent 自己不知道的事（專案慣例、內部規則、踩過的坑），通用
  常識不必重複。
- 內文控制在幾百行內；超過就拆成參考檔案。

## 修改現有的 skill

先用 `read_file` 讀完整的 SKILL.md，再用 `edit_file` 只改需要的地方，
不要整份重寫。改動 description 時要特別小心，它決定 skill 會不會被
載入。
