# 程式碼審查檢查清單

依重要程度排列。不是每一項都適用，挑和這次變更相關的檢查。

## 1. 正確性

- 邏輯是否符合需求？邊界條件（空值、空清單、0、負數、最大值）處理了嗎？
- 條件判斷有沒有寫反、少了 else、off-by-one？
- 錯誤有沒有被吞掉（空的 except / catch）？失敗時的狀態是否一致？
- 非同步程式：有沒有忘了 await、競態條件、資源沒有釋放？
- 改了函式的參數或回傳值，所有呼叫的地方都跟著改了嗎？

## 2. 安全性

- 使用者輸入有沒有直接拼進 SQL、shell 指令、檔案路徑或 HTML？
- 權限檢查：使用者能不能存取或修改不屬於自己的資料？
- 金鑰、密碼、token 有沒有寫死在程式碼或寫進 log？
- 檔案路徑有沒有可能跳出預期的資料夾（`../`）？

## 3. 資料與相容性

- 資料庫結構或檔案格式改了，舊資料還讀得到嗎？需要遷移嗎？
- 公開 API 或設定格式的改動會不會破壞既有使用者？
- 時區、編碼（UTF-8）、浮點數精度、金額計算是否正確？

## 4. 測試

- 新的行為有測試嗎？測試真的會在程式錯誤時失敗嗎？
- 修 bug 的變更有沒有加上能重現該 bug 的測試？
- 有沒有被跳過、註解掉或放寬條件的測試？

## 5. 效能

- 迴圈裡有沒有資料庫查詢或網路請求（N+1）？
- 有沒有把大量資料一次讀進記憶體？

## 6. 可維護性

- 命名是否清楚表達用途？
- 有沒有重複的程式碼可以用既有的函式取代？
- 註解是否說明「為什麼」，而不是重複程式碼在做什麼？
- 是否符合專案既有的風格與慣例？
