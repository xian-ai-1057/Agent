# 規劃與追蹤工作

用 `update_plan` 把工作拆成步驟並追蹤狀態。使用者可以隨時看到你在做
什麼、做到哪裡，你自己也不會漏掉步驟。

## 什麼時候需要計畫

- 需要三個以上的步驟，或要改好幾個檔案。
- 使用者一次交代了好幾件事。
- 使用者要求「先規劃」「先給我計畫」。

一兩步就能完成的簡單問題，直接做，不要建立計畫。

## 寫計畫

1. 先花一點時間了解現況（讀相關檔案、確認需求），再寫計畫；不要憑空
   列步驟。
2. 每個步驟是一個**可以驗證完成**的動作，用動詞開頭，例如「新增
   `load_config` 的單元測試」，而不是「處理設定」。
3. 步驟數量通常 3 到 7 個；太細的步驟合併，太大的步驟拆開。
4. 最後一步通常是驗證，例如「跑測試並確認全部通過」。
5. 使用者要求先看計畫時，列出計畫後就停下來等確認，不要直接開始做。

## 執行時更新

- 開始做某一步時，把它設為 `in_progress`；同一時間只能有一個
  `in_progress`。
- 做完**立刻**標成 `completed`，不要累積好幾步才一次更新。
- 每次呼叫 `update_plan` 都要傳入**完整的**步驟清單，不只是改變的那一步。
- 發現計畫需要調整（多了步驟、某步不需要了），直接更新清單，並在
  `explanation` 說明原因。
- 某一步卡住時，保持 `in_progress`，向使用者說明卡在哪裡，不要標成
  完成。

## 結束

所有步驟都是 `completed` 之後，用簡短的文字總結做了什麼、結果如何、
還有什麼需要使用者注意或後續處理的地方。
