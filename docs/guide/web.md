# 網頁版

在專案資料夾執行：

```bash
harness web                 # TypeScript 版，開啟 http://127.0.0.1:4321
pyharness web               # Python 版，開啟終端機顯示的網址（不必登入時結尾有 ?key=…）
pyharness web --port 8080   # 換埠號
```

兩個版本用同一份前端與同一套 API，畫面完全一樣。TypeScript 版和命令列共用同一份[對話紀錄](/guide/sessions)；Python 版只在自己電腦上用（不必登入）時也一樣，讓其他人使用時每個人的對話分開存放（見[帳號與成員](#帳號與成員)）。

- **對話**：回覆即時串流；工具呼叫收成「完成 N 個步驟」，每一步用看得懂的句子顯示（例如「讀取 `data/sales.csv`」、「執行 `python3 analyze.py`」），點開看參數與結果，執行指令的輸出以終端機的樣子呈現。工具回報的錯誤會標出來，agent 自己修正後繼續。
- **計畫清單**：agent 用 `update_plan` 列計畫時，執行期間會在輸入框上方顯示打勾清單（例如「計畫 2 / 4」），完成的項目會劃掉。
- **回覆的呈現**：表格、程式碼區塊（依語言上色，右上角有「複製」）、數學公式（KaTeX，`$…$` 與 `$$…$$`）。回覆底下可以複製整則內容。
- **權限確認**：需要同意的工具會停下來，可以「允許這一次」、「這個專案以後都允許」（寫進 `harness.yaml` 的 `allow`）或拒絕，也可以按 1、2、3。執行指令時直接顯示要執行的指令與資料夾；寫檔（`write_file`、`edit_file`）前右側面板會顯示預覽與差異。Python 版另外可以選「這段對話都允許」，見[減少確認](#減少確認)。
- **同時跑好幾段對話**：「工作中」列出所有正在跑、等你確認的對話，可以直接在列表上允許、拒絕或停止。
- **出錯與重試**：連不上模型時顯示原因，修好後按重試，從原本的訊息接著跑，不會重複送出。Python 版的伺服器在一輪跑到一半（或等你確認時）重新啟動的話，那段對話會顯示「服務重新啟動，這一輪中斷了」，按重試就接著做；中斷的工具呼叫不會被當成你拒絕。
- **設定**：查看專案的工具與 agent。每個人看到的設定頁都一樣，內容只能看。
- **[管理平台](#管理平台)**：模型連線、`maxTurns`、權限模式與規則（以及 Python 版的成員與[存取群組](#存取群組)）放在和聊天介面分開的管理平台（`/admin`），只有管理者能用；儲存時寫回 `harness.yaml` 並保留原本的註解。
- **外觀**：配色跟著作業系統的淺色或深色模式，也可以在設定頁右上角固定成淺色或深色（記在這個瀏覽器裡）。系統開啟「減少動態效果」時，畫面上的動畫會全部關閉。
- **手機**：螢幕較窄時，側欄收成左上角的選單。

管理平台修改 `harness.yaml` 時只改 `model`、`maxTurns` 與 `permissions` 那幾行，其他內容和註解都保持不動。檔案用了錨點（`&`、`*`）等特殊寫法、無法安全修改時，會請你直接編輯檔案。

Python 版另外會顯示：handoff 後換成接手的 agent、subagent 呼叫的工具即時列在交辦步驟底下、標出「對話已壓縮」的位置、訊息被[防護](/advanced/guardrails)擋下的原因。

## 管理平台 {#管理平台}

聊天介面對每個人都一樣：管理者和成員看到同樣的側欄、輸入框與設定頁。會影響所有人的設定集中在另外的**管理平台**，網址是 `/admin`，有自己的版面（左邊是管理平台的選單，底下的「回到聊天」回到聊天介面）：

| 分類 | 網址 | 內容 |
|---|---|---|
| 模型 | `/admin/model` | 模型連線（Python 版：供應商、金鑰、可以切換的模型；TypeScript 版：模型名稱與端點狀態）、`maxTurns` |
| 權限 | `/admin/permissions` | 權限模式與允許、先問我、拒絕規則 |
| 知識庫 | `/admin/knowledge` | 新增知識庫、上傳文件、試搜尋、檢索設定與維護者（Python 版，見[知識庫](#知識庫)） |
| 成員 | `/admin/members` | 新增成員、改角色、停用、重設密碼（Python 版要登入時才有，見[帳號與成員](#帳號與成員)） |
| 群組 | `/admin/groups` | 決定每位成員能用哪些模型、agent、工具組、知識庫與知識庫標籤（Python 版要登入時才有，見[存取群組](#存取群組)） |

- **怎麼進去**：要登入時，管理者在左下角的帳號選單點「管理平台」；不必登入（只有自己一個人，或 TypeScript 版）時，側欄底部「設定」下面直接有「管理平台」。也可以直接打開 `/admin`。
- **誰能用**：只有管理者。成員打開 `/admin` 只會看到「管理平台只有管理者能使用」與回到聊天的按鈕；就算直接呼叫 API，伺服器也會拒絕（`/api/settings/*`、`/api/admin/*` 都檢查管理者身分）。例外是知識庫的**維護者**：成員被指定為某個知識庫的維護者時，帳號選單也會出現「管理平台」，但裡面只有「知識庫」，而且只看得到自己維護的知識庫。
- **舊網址**：以前的 `/settings/model`、`/settings/permissions`、`/settings/members` 會自動換成管理平台對應的網址。設定頁（`/settings`）只剩工具與 agent。

管理平台和聊天介面是同一個網頁、同一個服務，不需要另外部署；登入狀態也共用，從帳號選單切過去不用重新登入。

以下幾節是只有 Python 版的伺服器才有的功能。用 TypeScript 版的 `harness web` 時，網頁會自動把這些按鈕藏起來。

## 帳號與成員 <span class="badge-py">Python 版</span> {#帳號與成員}

只在自己的電腦上用（`pyharness web` 只聽本機、沒有設定密碼、也沒有建立任何帳號）時**不必登入**，你就是這台電腦的管理者，一切和加入帳號之前一樣：

- 對話紀錄與長期記憶就是專案的 `.harness/sessions/` 與 `.harness/memory.json`，和 `pyharness chat`、`pyharness memory` 與 TypeScript 版共用，不會被搬走。
- agent 在專案根目錄工作，檔案面板看得到專案裡的檔案；上傳的檔案存在 `workspace/uploads/`（有設定沙盒時是 `sandbox.workspace/uploads/`）。沒有[工作資料夾](#工作資料夾)可以選。
- 只接受直接從這台電腦連進來的請求：帶有反向代理標頭（`X-Forwarded-For`、`Forwarded`、`X-Forwarded-Host`、`Via`）的請求一律拒絕（403），避免不小心把沒有密碼的管理者權限透過 nginx 這類反向代理開放出去。要透過反向代理使用，請設定 `HARNESS_WEB_PASSWORD`。
- 每次啟動產生一把**網址鑰匙**：請打開終端機顯示的完整網址（`http://127.0.0.1:4321/?key=…`），打開後鑰匙記在這個瀏覽器的 cookie 裡，網址列上的鑰匙會自動拿掉。沒有鑰匙的請求一律拒絕，所以沒有加轉送標頭的反向代理、`ssh -L` 或其他程式連進來也用不了。重新啟動後鑰匙會換，開著的網頁會顯示「請重新打開網址」。

讓其他人使用時（聽本機以外的位址、設定了 `HARNESS_WEB_PASSWORD`，或建立過帳號），每個人都要用自己的帳號登入：

- **第一位管理者**：第一次以這種方式啟動時，自動建立帳號 `admin`，密碼是網頁密碼（`HARNESS_WEB_PASSWORD`，沒有設定時自動產生並印在啟動訊息裡）。從舊版升級的話，原本的密碼不變，使用者名稱填 `admin` 即可。
- **新增成員**：管理者在「管理平台 → 成員」輸入使用者名稱（2–32 個英文字母、數字或 `.` `_` `-`）、顯示名稱與角色，伺服器產生一組密碼，**只顯示這一次**，請交給本人；成員登入後可以在帳號選單自己改密碼（至少 10 個字元）。忘記密碼時，管理者按「重設密碼」產生新的一組。
- **停用**：停用的成員立刻被登出，也不能再登入；他正在執行的對話會停下來（顯示「管理者變更了你的帳號」），開著的網頁也不再收到更新。改變一個人的角色時，他正在執行的對話同樣會停下來；權限判斷每次都讀最新的角色，被降級的管理者不能再用「全部直接執行」。至少要留一位可以使用的管理者，最後一位管理者不能降級或停用。
- 也可以用命令列管理：

  ```bash
  pyharness user add alice --name 愛麗絲      # 成員，印出產生的密碼
  pyharness user add boss --admin             # 管理者
  pyharness user list
  pyharness user passwd alice                 # 重設密碼（原本的登入全部失效）
  pyharness user disable alice                # 停用；enable 重新啟用
  ```

  帳號存在專案的 `.harness/harness.db`。`-p` 指定專案資料夾，寫在動作前後都可以。在本機模式下建立第一個帳號後，下次啟動就要登入。

| | 管理者 | 成員 |
|---|---|---|
| 自己的對話、檔案與[長期記憶](/advanced/memory) | ✓ | ✓ |
| 別人的對話與「我的檔案」 | 看不到 | 看不到 |
| [共用的工作資料夾](#工作資料夾) | 全部 | 被開放的 |
| [管理平台](#管理平台)：模型連線、權限設定、成員與群組管理 | ✓ | ✗（打開網址只看到沒有權限的說明） |
| 模型、agent、工具組、知識庫 | 全部 | 所屬[群組](#存取群組)開放的 |
| 「這個專案以後都允許」 | 寫進 `harness.yaml`，所有人適用 | 只記在自己的資料，只適用於自己在同一個資料夾的對話 |
| 這段對話「全部直接執行」（bypass） | ✓ | ✗ |
| 執行指令（`run_command`） | 「我的檔案」裡在伺服器上執行；共用資料夾裡在[沙盒](/advanced/sandbox)執行 | 在[沙盒](/advanced/sandbox)裡執行；沒有沙盒時不提供 |

登入後瀏覽器拿到一個 HttpOnly、SameSite=Strict 的 cookie，12 小時沒有使用就要重新登入（一直有在用時最多保留 14 天，每次使用往後延）。登出、改密碼或被停用後，開著的網頁最多 25 秒內就不再收到更新。管理者在成員頁重設自己的密碼時，這個瀏覽器會直接拿到新的登入，不必重新登入。

登入失敗的限制（都記在記憶體裡，伺服器重新啟動後歸零）：

- **同一個位址對同一個帳號名稱**連續輸錯 5 次後，每次再錯都要等一下才能再試：2 秒起跳、每次加倍，最多 60 秒；成功登入後歸零。只算同一個位址，所以別人從其他地方一直亂試你的帳號，也擋不到你。
- **同一個位址** 10 分鐘內最多錯 50 次（不分帳號名稱）。
- **同一個帳號名稱** 10 分鐘內所有位址加起來最多錯 200 次，擋下從很多位址一起猜同一個帳號。
- 同時送出的登入也算數（還沒有結果的就先占一次），同時最多 4 個登入在驗證密碼；格式不對的帳號名稱（不是 2–32 個英文字母、數字或 `.` `_` `-`）直接回「帳號或密碼不正確」，不會花時間驗證。
- 放在反向代理後面時，伺服器看到的位址都是反向代理的，請用 `--trusted-proxy` 告訴它反向代理的位址（見[部署到伺服器](/advanced/server)），否則所有人共用同一個位址的限制。

**每個人的資料分開存放**：

```text
.harness/harness.db                     帳號與登入狀態（只存密碼與登入 token 的雜湊）
.harness/users/<識別碼>/sessions/        對話紀錄（格式和以前相同）
.harness/users/<識別碼>/memory.json      長期記憶（harness.yaml 開啟 memory 時）
.harness/users/<識別碼>/permissions.json 成員自己「以後都允許」的工具
private/<識別碼>/                        「我的檔案」
```

別人的對話一律當成不存在（回 404），列表、搜尋與即時更新也只有自己的對話。

**從舊版升級（或從本機模式改成要登入）**：第一次以要登入的方式啟動時，原本的對話紀錄（`.harness/sessions/`）與長期記憶（`.harness/memory.json`）交給第一位管理者，其他成員看不到。專案裡的檔案（`workspace/`、上傳的檔案、報告）**不搬**，舊對話都放在一個只有這位管理者看得到的工作資料夾「**舊資料（專案資料夾）**」裡：它就是專案根目錄，所以舊對話裡的附件與檔案卡片照原本的路徑都打得開。這個資料夾**唯讀**（它包含 `agents/`、`tools/`、`harness.yaml`，agent 只能讀舊檔案，不能寫入），碰不到 `.harness/`、`private/` 與任何以點開頭的檔案，也不能執行程式或指令（沒有 `run_python` 與 `run_command`，沙盒會掛載整個專案）；要用程式分析舊檔案，請把它上傳到其他資料夾再開新的對話。搬移只做一次（記在 `.harness/users/migrated.json`），不會覆蓋任何檔案。之後 `pyharness chat` 建立的對話仍然存在 `.harness/sessions/`，不會出現在網頁上。

升級後要注意：預設的「共用」資料夾換成新的 `shared/`，**舊的 `workspace/` 不會再自動分享給所有成員**。要讓大家看到舊檔案，請把需要的檔案搬進 `shared/`，或在 `harness.yaml` 的 `workspaces` 明確開放（見下一節）。

## 存取群組 <span class="badge-py">Python 版</span> {#存取群組}

要登入時，管理者用**群組**決定每位成員能用什麼；成員登入後只看得到、也只能用群組開放給他的東西。做法參考 LiteLLM 的 access groups 與 MaiAgent 的角色權限：先把資源開放給群組，再把人放進群組。

在「管理平台 → 群組」（`/admin/groups`）設定。每個群組可以指定五種資源，每一種選「全部」（之後新增的也包含在內）或「指定」再勾選：

| 資源 | 來源 | 沒有開放時 |
|---|---|---|
| 模型 | 模型選單裡的模型（見[選擇模型、工具與 skills](#選擇模型工具與-skills)） | 模型選單看不到；對話原本選的模型被收回時，改用開放清單的第一個 |
| Agent | `agents/` 底下的 agent | 新對話看不到，也不能繼續用它的舊對話 |
| 工具組 | 內建的 `files`、`shell` 等、`tools/` 底下的檔案、`harness.yaml` 的 `mcpServers` | 工具從 ＋ 選單與設定頁消失，執行時也不會交給模型 |
| 知識庫 | [知識庫](#知識庫)（`knowledge/` 與 `harness.yaml` 的 `knowledgeBases`） | 對話的知識庫選單看不到，`search_knowledge` 也搜尋不到；agent 設定的知識庫全部沒有開放時，這個 agent 沒有 `search_knowledge` |
| 知識庫標籤 | 知識庫裡文件的[標籤](/advanced/knowledge#依部門限制可以搜尋的文件) | `search_knowledge` 搜尋不到這些標籤的文件（沒有標籤的文件所有人都搜尋得到） |

規則：

- **「所有人」群組**：內建、不能刪除或改名，每位成員自動屬於它。剛升級時它什麼都開放，所以原本的成員用起來和以前一樣；要收緊時，先把「所有人」改成大家都能用的最小範圍，再為各部門建立群組。
- **新建的群組預設什麼都沒有開放**，勾選後才有。
- **好幾個群組加起來算**：一個人能用的是他所屬群組開放範圍的聯集。
- **管理者不受群組限制**，看得到、也能用全部。
- 限制在伺服器上執行：成員就算直接呼叫 API，也不能選沒有開放的模型、agent 或工具；知識庫搜尋時伺服器會再和 agent 自己的 `labels` 取交集。
- 什麼模型或 agent 都沒有開放時，成員在新對話頁看到「管理者還沒有開放可以使用的模型給你，請聯絡管理者」。
- 群組存在 `.harness/harness.db`。修改後立刻生效，開著的網頁會自動更新；已經在執行的那一輪不受影響，下一輪開始照新的設定。

預算與用量上限之後再做。

## 知識庫 <span class="badge-py">Python 版</span> {#知識庫}

[知識庫](/advanced/knowledge)可以依主題或部門分成好幾個，在「管理平台 → 知識庫」（`/admin/knowledge`）管理，不必手動改檔案：

- **新增知識庫**：填識別碼（小寫英文、數字、`-`、`_`）、名稱與說明。會寫進 `harness.yaml` 的 `knowledgeBases` 並建立 `knowledge/<識別碼>/` 資料夾。說明會交給 agent，讓它知道這個知識庫裡有什麼。
- **文件**：上傳 `.md`、`.txt`、`.pdf`、`.docx`、`.pptx`、`.xlsx`，已有的文件按「更新」換成新版本，或刪除。列表下方顯示索引的檔案數、片段數，以及讀不了而被略過的檔案。文件改了以後下一次搜尋就會重建索引。
- **試搜尋**：輸入問題，看會找到哪些片段與分數，用來調整門檻。
- **設定**：名稱、說明、檢索設定（embedding 模型、切片長度、reranker、門檻；空白時沿用 `knowledge` 區塊的設定）與維護者。
- **拿掉知識庫**：只從 `harness.yaml` 拿掉，資料夾與文件都留著。預設知識庫不能拿掉；還有 agent 設定成要用它時，要先修改那個 agent。

**維護者**：管理者可以為每個知識庫指定維護者（要登入時才有）。維護者可以上傳、更新、刪除那個知識庫的文件並試搜尋，但不能改設定、不能新增或拿掉知識庫，也看不到別的知識庫。適合讓各部門自己更新自己的文件。維護者名單存在 `.harness/harness.db`。

**誰可以搜尋**：管理者不受限制；成員能搜尋哪些知識庫由[存取群組](#存取群組)決定，知識庫裡再用標籤做更細的限制。

**在對話裡選擇**：輸入框的 ＋ →「知識庫」列出這個人可以搜尋、且 agent 有用知識庫時可以選的知識庫，預設勾選 agent 設定的知識庫，可以多勾幾個或全部取消。選了好幾個時，結果合併排序，出處前面標上知識庫名稱。改過的選擇會以「知識庫 A、B」（全部取消時是「知識庫 不搜尋」）標籤顯示在輸入框裡，按 × 回到 agent 的預設。

API（`/api/knowledge`）：

| 方法 | 路徑 | 誰可以用 |
|---|---|---|
| `GET` | `/api/knowledge` | 管理者與維護者（維護者只看到自己的） |
| `POST` | `/api/knowledge` | 管理者：新增知識庫 |
| `PATCH`、`DELETE` | `/api/knowledge/:id` | 管理者：修改設定、維護者，或拿掉知識庫 |
| `GET`、`POST`、`DELETE` | `/api/knowledge/:id/documents` | 管理者與該知識庫的維護者：列出、上傳（`?dir=` 放進子資料夾、`?replace=` 換掉既有的檔案）、刪除文件（`?path=`） |
| `POST` | `/api/knowledge/:id/search` | 管理者與該知識庫的維護者：試搜尋 |

## 工作資料夾 <span class="badge-py">Python 版</span> {#工作資料夾}

要登入時，每段對話都在一個**工作資料夾**裡進行：agent 的檔案工具、執行指令與沙盒的 `run_python` 都只看得到這個資料夾，上傳的檔案也存在裡面，訊息裡的附件、工具的路徑與產生的檔案都相對於它。新對話預設是自己的「我的檔案」，在輸入框選別的資料夾。**資料夾只能在開始對話前選擇**：之前的附件與檔案卡片都相對於它，對話開始後就不能再換（`PUT /api/sessions/:id/options` 帶不同的 `folder` 會回 400）。只在自己電腦上用（不必登入）時沒有工作資料夾，agent 在專案根目錄工作。

- **我的檔案**：每個人自己的資料夾（`private/<識別碼>/`），只有本人看得到。
- **共用資料夾**：管理者在 `harness.yaml` 開放：

  ```yaml
  workspaces:
    - name: 營收分析
      path: workspace/revenue   # 相對於專案，或絕對路徑（例如掛載進來的資料夾）
      members: all              # 或使用者名稱的清單，例如 [alice, bob]；管理者都看得到
      writable: true            # false 時 agent 不能寫入或修改（沙盒也唯讀掛載），也不能上傳
    - name: 公告
      id: notice                # 選填：資料夾的識別碼，預設由 path 產生
      path: workspace/notice
      writable: false
  ```

  沒有寫 `workspaces` 時，有一個所有人都能用的「共用」資料夾：專案的 `shared/`（第一次使用時建立）。舊版單人網頁版的 `workspace/` 不會自動分享給所有人。
- **舊資料（專案資料夾）**：從舊版升級時才有，唯讀，只有接收舊資料的管理者看得到（被降為成員或停用後就看不到）（見[帳號與成員](#帳號與成員)的「從舊版升級」）。

共用資料夾不能和 `.harness/`、`private/`、`harness.yaml`、`AGENTS.md`、`agents/`、`tools/`、`skills/` 重疊（agent 可能藉此改寫專案的設定或讀到別人的資料），彼此也不能互相包含；寫錯時 `pyharness web` 啟動就會報錯。用 Docker 部署時，共用資料夾要放在專案裡（沙盒透過 volume 掛載專案）。

`run_command`（`shell`）只有管理者在自己的「我的檔案」裡才在伺服器上執行，而且 `cwd` 限制在工作資料夾裡；它可以執行任何指令，所以不會被資料夾擋住。在共用資料夾裡，管理者的指令也在沙盒執行（沒有沙盒時不提供）：成員可以在共用資料夾放檔案（例如 `.git/config`、和 Python 模組同名的檔案），讓 `git status` 這類看似無害的指令在伺服器上執行成員寫的程式。之後的企業版會把管理者的指令全部移進沙盒。

停用帳號（網頁或 `pyharness user disable`）或管理者重設別人的密碼後，那個人正在執行的對話會停下來；從指令列停用時，對話在下一次要執行工具前停下來，之後也不能再執行任何工具。

檔案工具、檔案面板與上傳都**不跟著捷徑（symlink）走**：從工作資料夾開始一層一層用 `O_NOFOLLOW` 打開，路徑上任何一層是捷徑就拒絕，列資料夾時也不列出捷徑。沙盒裡的程式可以在工作資料夾裡建立捷徑，這樣它就沒辦法讓伺服器讀寫資料夾外面的檔案（例如把 `uploads/` 換成指向 `tools/` 的捷徑）。

要登入時，`web_fetch` 不能讀內部網路：本機、私有網路（`10.x`、`172.16–31.x`、`192.168.x`）、link-local（含雲端主機的中繼資料服務 `169.254.169.254`）、IPv6 unique-local、CGNAT（`100.64.0.0/10`）與未指定位址都會被拒絕，每次轉址都重新檢查，連線時也只連到檢查過的位址。管理者確實需要讀內網的網址時，在 `harness.yaml` 加上下面的設定，只對管理者自己的對話生效（成員一律不能讀）：

```yaml
web:
  allowPrivateNetworks: true
```

## 選擇模型、工具與 skills <span class="badge-py">Python 版</span> {#選擇模型工具與-skills}

每段對話可以各自決定用哪個模型、哪些工具和 skills，從下一則訊息開始生效：

- **模型**：輸入框右下角的模型名稱，點開可以搜尋，並標出「看得懂圖片」與「預設」。對話進行到一半也可以換。
- **＋ 選單**：輸入框左下角的 ＋ 可以上傳檔案，或在「Skills」、「工具」、「知識庫」裡勾選這段對話要用的項目。選好的 skill、關掉的工具與改過的知識庫會以標籤顯示在輸入框裡，按 × 取消。
  - 工具只能在 agent 原本就有的範圍內關閉，不能多加。
  - 勾選的 skill 會在送給模型的系統提示裡註明「先讀取這些 skill」。

清單裡的模型來自：專案的預設模型、各個 agent 檔案寫的模型，以及 `harness.yaml` 的 `models`。要多開放幾個模型給使用者選，在 `harness.yaml` 加上：

```yaml
models:
  - openai/gpt-5
  - name: anthropic/claude-haiku-4-5
    label: Claude Haiku（快）
```

每一項可以只寫 litellm 的模型名稱，或用 `label` 指定顯示的名稱。模型需要的金鑰要另外設定（見[設定模型](/guide/model)）。這段對話的選擇（含[工作資料夾](#工作資料夾)）存在對話紀錄旁邊的 `<對話>.meta.json`（要登入時在 `.harness/users/<識別碼>/sessions/`），伺服器重新啟動後仍然有效；選過的模型之後從清單移除時，改用 agent 原本的模型。

## 減少確認 <span class="badge-py">Python 版</span> {#減少確認}

- **這段對話都允許**：同意一個工具時選它，這段對話之後再用這個工具都不再問。只記在這段對話的 `.meta.json`，伺服器重新啟動後仍然有效，**不會寫進 `harness.yaml`**，其他對話照樣會問。
- **以後都允許**：管理者選它時寫進 `harness.yaml` 的 `allow`，所有人都適用；成員選它時只記在自己的 `.harness/users/<識別碼>/permissions.json`，只適用於自己在同一個工作資料夾裡的對話（成員不能放寬別人的權限）。
- **同樣的呼叫不再問**：在同一段對話裡同意過的呼叫（同一個工具、參數完全相同，例如讀同一個網址），之後再出現時直接執行。拒絕過的呼叫下次仍然會問。

## 預覽檔案 <span class="badge-py">Python 版</span> {#預覽檔案}

點訊息裡的附件、回覆底下的檔案卡片，或工具步驟裡的檔名，右側面板就會打開那個檔案。agent 用沙盒的 `run_python` 新增或修改的檔案（圖表、CSV、簡報等）也會出現在檔案卡片裡：伺服器執行前後比對工作目錄，把這些檔案的路徑接在工具結果後面（見[沙盒](/advanced/sandbox#產生的檔案)）。面板有三個分頁：

- **預覽**：圖片直接顯示；PDF 用瀏覽器內建的檢視器；Markdown 排版後顯示；CSV 顯示成表格（前 200 列）；文字與程式碼依語言上色。HTML、SVG 一律顯示原始碼，不會在網頁裡執行。其他格式（壓縮檔、舊版的 `.doc`、`.xls`、`.ppt`）顯示大小和「下載」。
- **Word、PowerPoint**（`.docx`、`.pptx` 等）：伺服器用 LibreOffice 轉成 PDF 顯示，版面、圖表、字型和 Office 相同（`GET /api/files/pdf?folder=…&path=…`）。有設定[沙盒](/advanced/sandbox)時在沙盒的容器裡轉換，檔案不在伺服器上解析；沒有沙盒時只有不必登入的本機模式會用這台電腦安裝的 LibreOffice（macOS 可以 `brew install --cask libreoffice`）。轉好的 PDF 依檔案內容快取在 `.harness/previews/`（最多 500 MB，從最久沒用的開始刪），內容沒變就不再轉換。不能轉換時（沒有 LibreOffice、檔案損毀）改在瀏覽器裡顯示「簡易預覽」，版面可能和 Office 不一樣。超過 30 MB 的檔案請下載。
- **Excel**（`.xlsx`、`.xlsm`）：每個工作表一個分頁，顯示成有欄名、列號的表格（前 1000 列、100 欄），日期、百分比與千分位照儲存格的格式顯示；公式顯示存檔時算好的結果，沒有結果時顯示公式本身。
- **變更**：寫檔前後的差異。
- **這段對話的檔案**：這段對話上傳與寫入的所有檔案。

右上角可以下載，或切換成全螢幕（按 Esc 離開）。拖曳對話區與面板之間的分隔線可以調整面板寬度（對話區至少保留 360px），雙擊分隔線回到預設寬度；也可以按 Tab 移到分隔線，用左右方向鍵調整、Home／End 到最寬／最窄、Enter 回到預設。寬度記在這個瀏覽器，下次打開面板時沿用。視窗太窄、面板浮在畫面上時不能拖曳。

能預覽的範圍和 agent 相同：只有這段對話的[工作資料夾](#工作資料夾)裡的檔案（`GET /api/files?folder=…&path=…`，伺服器先確認你可以使用那個資料夾），不能存取以點開頭的檔案或資料夾，絕對路徑與捷徑（symlink）也不行。檔案從打開的那一刻起就固定（伺服器直接從開好的檔案送出，支援 `Range`），中途被換掉也不會送出別的檔案。

從網頁執行時，伺服器會在 agent 的指示後面加一段「網頁版說明」（不會改到 `agents/` 裡的檔案）：使用者只有瀏覽器，打不開伺服器上的資料夾、也不能執行指令；它只看得到這段對話的工作資料夾；產生的檔案會以檔案卡片出現，提到檔案時用相對於工作資料夾的路徑；引用數字時只用程式實際印出來的值。

## 管理對話 <span class="badge-py">Python 版</span> {#管理對話}

- **搜尋**：側欄的「搜尋對話」或按 ⌘K（Windows 為 Ctrl+K），可以用關鍵字找對話標題與訊息內容，↑↓ 選擇、Enter 開啟。
- **分組**：側欄的「最近的對話」依最後更新時間分成「今天」、「昨天」、「過去 7 天」與「更早」。
- **重新命名、移到專案與刪除**：滑到對話上，按右邊的 ⋮。刪除前會先確認，對話紀錄會直接刪掉、無法復原；正在跑或等你確認的對話不能刪除，先停止它。
- **對話紀錄**：側欄的「對話紀錄」列出所有對話，可以搜尋標題與內容、依專案篩選。勾選好幾段對話（或勾最上面的全選）後，可以一起「移到專案」或「刪除」；還在執行或等你確認的對話會略過，畫面會告訴你略過了幾段。

### 專案 {#專案}

和 ChatGPT、Claude 一樣，可以建立「專案」把對話分類整理（例如「十月營運月報」）。這裡的專案只是對話的分類，和 harness 的專案資料夾（`harness.yaml` 所在的地方，名稱顯示在側欄的 Harness 旁邊）無關。

- 側欄「專案」旁的 ＋ 新增專案；點專案打開專案頁，列出裡面的對話，可以搜尋、多選後移走或刪除。
- 專案頁的「在這個專案開新對話」開始的對話，會直接放進這個專案。
- 專案頁右上的 ⋮ 可以重新命名或刪除專案。刪除專案**不會**刪除裡面的對話，對話改成未分類。
- 每個人只看得到自己的專案（要登入時存在 `.harness/users/<識別碼>/categories.json`，不必登入時是 `.harness/categories.json`）；對話屬於哪個專案記在對話的 `.meta.json`。名稱最多 50 個字，同一個人的專案名稱不能重複。
- API：`GET`／`POST /api/categories`、`PATCH`／`DELETE /api/categories/:id`、`PATCH /api/sessions/:id` 的 `category`（`null` 表示移出專案）、`POST /api/sessions` 的 `category`，以及一次處理好幾段對話的 `POST /api/sessions/bulk {action: "delete" | "move", ids, category}`（一次最多 500 段，回傳處理好的與略過的對話）。

## 回覆的評價 <span class="badge-py">Python 版</span> {#回覆的評價}

每則回覆底下有讚與倒讚。倒讚時可以勾選原因（資訊不正確、沒有照要求做、回答不完整、太長），再補充說明。評價記在這段對話裡，同時附加到專案的 `.harness/feedback.jsonl`（時間、對話、評價的人、使用的模型、評價與原因），方便之後整理哪些回答不好。

## 在網頁上連接模型 <span class="badge-py">Python 版</span> {#在網頁上連接模型}

還沒有設定金鑰時，打開網頁會先看到「還沒有連接模型」的說明，管理者按「前往管理平台」設定；之後要更換，到「管理平台 → 模型」。成員看到的是請管理者設定的說明。

1. 選供應商：Anthropic、OpenAI、Google、OpenRouter、Ollama（本機模型，不需要金鑰），或自己的 OpenAI 相容端點（LiteLLM Proxy、vLLM 等，填端點網址）。
2. 貼上金鑰（或填好端點網址）。**填好後會自動列出這家供應商或端點可以用的模型**，從選單選一個當作預設模型；清單裡沒有的，選「其他（自行輸入模型名稱）」直接填。列不出來時（例如端點不支援 `/models`）會說明原因，一樣可以直接填。
3. 需要的話，在「對話中可以切換的模型」勾選其他模型，它們會出現在輸入框的模型選單（寫進 `harness.yaml` 的 `models`，原本有寫 `label` 的模型保留顯示名稱）。
4. 按「測試連線並儲存」。**伺服器會先用新的設定實際連一次模型，連得上才儲存**；金鑰打錯、模型名稱不對或連不到伺服器時，會顯示原因（依錯誤的種類判斷，後面附上原始的錯誤訊息），原本的設定保持不變。

列出模型的方式：OpenAI 相容端點用 `GET /models`（網址沒有 `/v1` 而找不到時再試 `/v1/models`）；Anthropic、OpenAI、Google、OpenRouter 用各自官方的模型清單 API（OpenAI 只留對話用的模型，Google 只留支援 `generateContent` 的模型）；Ollama 用 `GET /api/tags`。API 是 `POST /api/settings/models/discover {provider, baseURL, apiKey}`，只有管理者能用；金鑰留空時用已經存好的金鑰，但**換成別的端點網址時不會送出存好的金鑰**。勾選的模型用 `PUT /api/settings/models {models}` 儲存。

儲存的內容：

- 模型名稱寫進 `harness.yaml` 的 `model`。
- 金鑰與端點網址存在專案的 `.harness/secrets/env.json`，只有執行 pyharness 的使用者能讀（權限 600）。網頁上之後只顯示「已設定」，不會再顯示內容。
- 存起來的設定在每次啟動時套用，**優先於啟動時的環境變數**；同一個專案的 `pyharness chat`、`pyharness run` 也會使用。要回到只用環境變數，刪掉 `.harness/secrets/env.json` 再重新啟動。

::: warning
內建的檔案工具不能存取 `.harness/secrets/`，沙盒也掛載不到它。但 `shell` 的 `run_command` 可以執行任何指令（讀得到這個檔案，也讀得到環境變數），所以架給別人用的 agent 不建議開啟 `shell`。
:::

清單以外的供應商（litellm 支援的其他服務）仍然用原本的方式：在 `harness.yaml` 寫模型名稱、用環境變數提供金鑰（見[設定模型](/guide/model)）。TypeScript 版的端點與金鑰一律來自環境變數，網頁上只顯示狀態。

## 上傳檔案 <span class="badge-py">Python 版</span> {#上傳檔案}

按輸入框左下角的迴紋針、把檔案拖進輸入框，或直接貼上，就能把檔案附在訊息上。

上傳的檔案存在這段對話的[工作資料夾](#工作資料夾)底下的 `uploads/`（預設是自己的「我的檔案」，`POST /api/uploads?folder=…`）。沙盒每一輪都把工作資料夾掛載到 `/workspace`，所以 agent 可以直接用 `run_python` 解析，也可以用 `files` 工具讀取。唯讀的資料夾不能上傳。只在自己電腦上用（不必登入）時和以前一樣存在 `workspace/uploads/`（有設定沙盒時是 `sandbox.workspace/uploads/`），附件的路徑是 `workspace/uploads/…`。`uploads/` 被換成捷徑（symlink）或檔案時拒絕上傳。

- 選好檔案就開始上傳，全部上傳完才能送出；只附檔案、不打字也可以送出。
- 送出時，伺服器會在訊息後面加上每個附件的路徑，讓模型知道檔案在哪裡：

  ```text
  幫我分析這份報表

  [附件] uploads/十月_業績.xlsx（run_python 裡的路徑：/workspace/uploads/十月_業績.xlsx）
  ```

  路徑相對於工作資料夾。網頁上這幾行會顯示成訊息底下的檔案標籤。只能附上這段對話的工作資料夾裡上傳的檔案。
- 檔名裡的空白與特殊字元會換成底線，同名的檔案會自動加上 `-2`、`-3`。
- 單一檔案預設最多 50 MB，用 `pyharness web --max-upload-mb 200` 調整。檔案邊收邊寫入磁碟，不會整個放進記憶體。
- 上傳的檔案不會自動刪除；同一個工作資料夾的對話共用同一個 `uploads/` 資料夾。
- 上傳只接受帶有特定標頭、來自同一個網站的請求，其他網站無法借用使用者的登入狀態上傳檔案。

## 自動建立助手 <span class="badge-py">Python 版</span> {#自動建立助手}

資料夾是空的（或還不存在）時，`pyharness web` 會自動建立一個可以直接使用的通用助手，不必先執行 `pyharness new`：

```bash
pyharness web -p ~/my-assistant
```

這個助手可以讀寫專案裡的檔案、列計畫、讀取網頁、記住使用者交代的事；這台電腦能使用 Docker 時，還會開啟[沙盒](/advanced/sandbox)，讓它寫程式分析上傳的檔案。建立的就是一般的專案（`harness.yaml`、`agents/main.md`、`AGENTS.md`），之後可以照自己的需要修改。資料夾裡已經有其他檔案、卻沒有 `harness.yaml` 時不會自動建立，以免指錯位置。

## 讓其他電腦連線

伺服器可以執行專案的工具，所以預設只接受本機連線，並拒絕其他網站送來的請求。

- **Python 版**：每個人用自己的帳號登入（見[帳號與成員](#帳號與成員)），可以用 `--allowed-host` 限制網址，見[部署到伺服器](/advanced/server)或[快速部署](/guide/deploy)。
- **TypeScript 版**：沒有登入機制。要讓別台電腦連線時，用 `--host 0.0.0.0` 並自行加上防火牆或反向代理的保護；要架給團隊用，建議用 Python 版。

## 修改網頁本身

先在專案資料夾執行 `harness web`（或 `pyharness web`），再在這個 repo 執行 `npm run dev:web`，Vite 會把 `/api` 轉給它。原始碼在 `web/`，前後端之間的資料格式定義在 `src/web/protocol.ts`，Python 版的 `python/src/harness/web/` 要回傳一樣的格式。

`npm run build` 會把前端打包到 `dist/public`，並複製一份到 `python/src/harness/web/static`。Python 版用 pip 從 git 安裝時沒有 Node.js 可以打包，所以這份打包結果要一起提交。
